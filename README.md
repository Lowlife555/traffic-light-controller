# Traffic Light Controller — ARM (register level) + FPGA (Verilog)

A pedestrian-crossing traffic-light controller implemented **twice**, on two completely different platforms, as Year-2 undergraduate coursework (EL2242 – Digital Systems / Embedded Systems). Both halves drive the same **SSD1306 OLED** as their status display.

1. **Bare-metal ARM firmware** on an STM32L476RG — written directly against CMSIS registers (no HAL), with the controller state machine stepped from a 1 ms timer interrupt.
2. **FPGA logic** in Verilog for an Altera/Intel Cyclone board — a synthesisable state machine with a hand-written I²C master that drives the OLED, an 8-way DIP-switch traffic-density input and a buzzer.

The two halves are independent implementations of the same specification, which is why the repository also keeps several iterations of each side.

## ARM implementation

- **Target:** STM32L476RG, Keil MDK-ARM project. The device pack supplies `RTE\Device\STM32L476RGTx\`; only `main.c` and the `.uvprojx` are committed (`RTE/` and the vendor library are git-ignored and regenerated by the toolchain).
- **Style:** register-level — `RCC`, `GPIO`, `ADC1`, `I2C1` and `TIM3` are configured by direct register writes; no ST HAL and no CubeMX-generated code.
- **Clock:** `SystemClock_Config_80MHz()` — the MSI is multiplied through the PLL by `RCC->PLLCFGR = PLLSRC_MSI | (40 << 8)` with PLLR = 2, i.e. 4 MHz × 40 ÷ 2 = **80 MHz**.
- **Control loop:** `TIM3->PSC = 80-1` and `TIM3->ARR = 1000-1` give a **1 ms** update interrupt; `TIM3_IRQHandler` clears `UIF` and steps the 4-state machine `IDLE → FLASH → YELLOW → PED` with one-second ticks.
- **Inputs / outputs:** traffic and pedestrian LEDs through `GPIOA->BSRR`; a start-and-poll `ADC1` conversion (`ADC1->SQR1 = 6 << 6`, read from `ADC1->DR`); the **SSD1306 OLED** written over I2C1 (`I2C1->TIMINGR = 0x10D1143A`, slave address `0x78`, command/data control bytes and `OLED_ShowString`).
- The **other three ARM folders** are simpler iterations: `traffic-light-lite` and `traffic-light-v1` are GPIO-only 3-state versions (`CAR_GREEN / CAR_YELLOW / PED_CROSS`) with no timer, ADC or display; `register-practice` only enables the GPIOA clock.

## FPGA implementation (Verilog)

Two complete designs sit side by side. Both take a 50 MHz clock and an asynchronous active-low reset.

### `quartus-v2/traffic_light_V2.v` — the design that drives the OLED

| Element | What the code does |
|---|---|
| Traffic state machine | 4 states `IDLE / FLASH / YELLOW / PED_CROSS`, one tick per second from a 26-bit counter (`cnt_1hz` counts to 49 999 999); a pedestrian request is latched from either button (`key_ped`, `key_ped2`) and cleared in `PED_CROSS` |
| Traffic-density input | the 8 DIP switches `sw_flow` are read active-low (`sw_active = ~sw_flow`) and summed into `sw_count`; `flow_val = sw_count × 12` (≈ 0–96 %) and the pedestrian wait becomes `dynamic_wait = 5 + (sw_count × 15) / 8` seconds (5–20 s) |
| Lights | active-low `led_r` / `led_y` / `led_g` and `ped_led_r` / `ped_led_g`; the vehicle green flashes during `FLASH` (`cnt_1hz[24]`) |
| OLED link | hand-written native I²C master: 9 states (`IDLE → START → SEND_ADDR → ACK_ADDR → SEND_CTRL → ACK_CTRL → SEND_DATA → ACK_DATA → STOP`), slave address `0x78`, control byte `0x00` for commands and `0x40` for data, `oled_sda` driven open-drain (tri-state) with an internal weak pull-up |
| OLED initialisation | the 24-command SSD1306 sequence held in `init_cmds[0..23]` (`0xAE 0x20 0x02 0x8D 0x14 0xAF 0xB0 0xC8 0xA1 … 0xDA 0x12 0xDB 0x40`) |
| Character ROM | `get_char` returns 40-bit glyphs (5 columns × 8 rows) for letters A–Y, digits 0–9 and the symbols `:` `[` `]` `*` `-` and space |
| Display state machine | 6 states `M_INIT / M_CLEAR_POS / M_CLEAR_DATA / M_POS / M_DRAW / M_IDLE`, drawing four lines: `TRAFFIC SYSTEM`, `TIME: NN SEC`, `STATE: GREEN / FLASH / WAIT / CROSS` and `F NN[**********]` with a 10-cell flow bar |
| Buzzer | high-active `buzzer` output driven from the `beep_timer` divider |
| Constraints | `pin_planner.tcl` and `traffic_light_V2.qsf` |

### `quartus-vg/` and `quartus-vg-demo/` — the seven-segment variant

| Module | Role |
|---|---|
| `traffic_lights_VG.v` | Top level: the same two-mode controller (two pedestrian buttons plus a `btn_veh_sensor` input), motor and pedestrian LED outputs. Its header comment states the four intended functions: dual mode, potentiometer-adjusted base green time, sensor-based compensation and the display switching to the raw reading while the potentiometer is turned. |
| `adc_081s021_driver.v` | 3-wire SPI master for an **ADC081S021** (`ad_cs`, `ad_sclk`, `ad_miso`, 8-bit result, ≈ 250 kHz SCLK generated by dividing the 50 MHz clock by 200) — reads the potentiometer that sets the base vehicle-green time |
| `display_6digit_driver.v` | **6-digit seven-segment display multiplexer** (`seg_data[7:0]`, `seg_sel[5:0]`, dynamic scan with a `hex2seg` font): the three left digits show the ADC value while `adc_en` is asserted, the middle digit acts as a separator and the two right digits show the countdown |
| `buzzer_pwm_driver.v` | PWM buzzer output |
| `tb_traffic_lights.v` | Empty placeholder bench (0 bytes) kept with this variant |
| `Waveform1.vwf` | The Quartus simulation waveform used to check this variant |

**Control features implemented in the FPGA design**

- Both designs: automatic timed operation **or** pedestrian push-button request on either of two crossing buttons.
- OLED design: the eight DIP switches set the traffic-density figure, which both scales `flow_val` and derives the 5–20 s pedestrian wait; the OLED shows the current state, the countdown and the flow bar; the buzzer sounds for the pedestrian phase.
- Seven-segment variant: a vehicle-sensor button compensates the green phase, and the potentiometer read through the SPI ADC sets the base green time — the display switches from the countdown to the raw ADC value while it is adjusted, so the effect is visible on the board.
- Quartus pin assignments are kept as `.tcl` scripts (`pin_planner.tcl` in `quartus-v2/`, `pin_assignment.tcl` in both `quartus-vg*` folders, `pin_assignments.tcl` in `simulation/`), and the `.qsf` files list the pin assignments and device settings.

## How to build

- **ARM:** open the `.uvprojx` in Keil MDK-ARM with the STM32L4xx device pack. Only `main.c` and the project file are committed — `RTE/` and the CMSIS/HAL library are regenerated by the toolchain and are git-ignored.
- **FPGA:** open the `.qpf` in Intel/Altera Quartus, or recreate the project and run the provided `.tcl` script to re-apply the pin constraints.

# 交通灯控制器 —— ARM（寄存器级）+ FPGA（Verilog）

同一个行人过街交通灯控制器，用**两种完全不同的平台各实现了一遍**：大二课程作业（EL2242 数字系统 / 嵌入式系统）。两套实现的**状态显示都用同一块 SSD1306 OLED**。

1. **裸机 ARM 固件**：STM32L476RG，**直接操作 CMSIS 寄存器**（不用 HAL），状态机由 **1 ms 定时器中断**推进。
2. **FPGA 逻辑**：Altera/Intel Cyclone 开发板上的可综合 Verilog —— 状态机 + **自写 I²C 主控驱动 OLED** + 8 位拨码开关车流输入 + 蜂鸣器。

两部分是同一份需求书的两个独立实现，所以仓库里也保留了各自的多个迭代版本。

## 仓库结构

```

  register-level/       最终版 ARM 控制器：纯 CMSIS 寄存器操作、1 ms TIM3 中断、
                        4 个状态、ADC1 输入、I2C1 接 OLED        （Keil MDK 工程）
  traffic-light-lite/   GPIO 精简版：3 个状态，用 GPIOA->BSRR 直写 + 阻塞延时，
                        没有定时器 / ADC / 显示                    （Keil MDK 工程）
  traffic-light-v1/     GPIO 版，3 个状态                         （独立 Keil 工程
                                                                    traffic_light_V1）
  register-practice/    学 CMSIS 时的最小点灯例程（只开 GPIOA 时钟）
fpga/
  quartus-v2/           OLED 设计：traffic_light_V2.v 内含交通状态机、自写 I²C 主控、
                        字符 ROM、OLED 显示状态机与蜂鸣器逻辑（Quartus 工程）
  quartus-vg/           数码管方案：顶层 + SPI ADC 驱动 + 蜂鸣器驱动 + 6 位数码管驱动；
                        该目录还放着 tb_traffic_lights.v 与仿真波形 Waveform1.vwf
  quartus-vg-demo/      数码管方案的演示版；目录里另有一个 OLED 驱动骨架

  simulation/           用于仿真的简化版（不含显示器）
```

## ARM 实现

- **目标**：STM32L476RG，Keil MDK-ARM 工程。器件包提供 `RTE\Device\STM32L476RGTx\`；仓库只入库了 `main.c` 与 `.uvprojx`（`RTE/` 与厂商库被 git 忽略，由工具链自行生成）。
- **风格**：寄存器级 —— `RCC`、`GPIO`、`ADC1`、`I2C1`、`TIM3` 全部直接写寄存器；不用 ST HAL，不用 CubeMX 生成代码。
- **时钟**：`SystemClock_Config_80MHz()` —— 以 `RCC->PLLCFGR = PLLSRC_MSI | (40 << 8)`（PLLR = 2）把 MSI 经 PLL 倍频，即 4 MHz × 40 ÷ 2 = **80 MHz**。
- **控制环**：`TIM3->PSC = 80-1`、`TIM3->ARR = 1000-1` → **1 ms** 更新中断；`TIM3_IRQHandler` 清 `UIF` 后以 1 秒节拍推进 4 态状态机 `IDLE → FLASH → YELLOW → PED`。
- **输入 / 输出**：机动车与行人 LED 通过 `GPIOA->BSRR` 直接置位；ADC1 单次转换（`ADC1->SQR1 = 6 << 6`，结果读 `ADC1->DR`）；**SSD1306 OLED** 走 I2C1（`I2C1->TIMINGR = 0x10D1143A`，从机地址 `0x78`，命令/数据控制字节与 `OLED_ShowString`）。
- **另外三个 ARM 目录**是更简单的迭代：`traffic-light-lite` 与 `traffic-light-v1` 是纯 GPIO 的三态版本（`CAR_GREEN / CAR_YELLOW / PED_CROSS`），没有定时器、ADC 与显示；`register-practice` 只开了 GPIOA 时钟。

## FPGA 实现（Verilog）

仓库里并排放着**两套完整设计**，都用 50 MHz 时钟与异步低电平复位。

### `quartus-v2/traffic_light_V2.v` —— 驱动 OLED 的那套设计

| 组成 | 代码实际做的事 |
|---|---|
| 交通状态机 | 4 个状态 `IDLE / FLASH / YELLOW / PED_CROSS`，由 26 位计数器 `cnt_1hz`（计到 49 999 999）产生 1 秒节拍；行人请求由两个按键（`key_ped`、`key_ped2`）之一置位，在 `PED_CROSS` 中清除 |
| 车流输入 | 8 位拨码开关 `sw_flow` 以低电平有效读取（`sw_active = ~sw_flow`）并求和为 `sw_count`；`flow_val = sw_count × 12`（约 0–96%），行人等待时间 `dynamic_wait = 5 + (sw_count × 15) / 8` 秒（5–20 s） |
| 灯控 | 低电平有效的 `led_r` / `led_y` / `led_g` 与 `ped_led_r` / `ped_led_g`；机动车绿灯在 `FLASH` 期间用 `cnt_1hz[24]` 闪烁 |
| OLED 链路 | 自写原生 I²C 主控：9 个状态（`IDLE → START → SEND_ADDR → ACK_ADDR → SEND_CTRL → ACK_CTRL → SEND_DATA → ACK_DATA → STOP`），从机地址 `0x78`，命令控制字节 `0x00`、数据控制字节 `0x40`，`oled_sda` 为三态开漏输出（内部弱上拉） |
| OLED 初始化 | `init_cmds[0..23]` 里的 **24 条** SSD1306 命令序列（`0xAE 0x20 0x02 0x8D 0x14 0xAF 0xB0 0xC8 0xA1 … 0xDA 0x12 0xDB 0x40`） |
| 字符 ROM | `get_char` 返回 **40 位**字模（5 列 × 8 行），含字母 A–Y、数字 0–9 以及 `:` `[` `]` `*` `-` 和空格 |
| 显示状态机 | 6 个状态 `M_INIT / M_CLEAR_POS / M_CLEAR_DATA / M_POS / M_DRAW / M_IDLE`，绘制四行：`TRAFFIC SYSTEM`、`TIME: NN SEC`、`STATE: GREEN / FLASH / WAIT / CROSS`、`F NN[**********]`（10 格车流进度条） |
| 蜂鸣器 | 高电平有效的 `buzzer`，由 `beep_timer` 分频驱动 |
| 约束 | `pin_planner.tcl` 与 `traffic_light_V2.qsf` |

### `quartus-vg/` 与 `quartus-vg-demo/` —— 数码管方案

| 模块 | 作用 |
|---|---|
| `traffic_lights_VG.v` | 顶层：同样是双模式控制器（两个行人按键 + `btn_veh_sensor` 输入），输出机动车与行人灯。文件头注释写明四项功能：双模式、电位器调节绿灯基础时长、传感器动态补偿、以及调节时数码管切换显示原始读数。 |
| `adc_081s021_driver.v` | **ADC081S021** 的三线 SPI 主控（`ad_cs`、`ad_sclk`、`ad_miso`，8 位结果，把 50 MHz 二分频 200 次得到约 250 kHz SCLK）—— 读电位器，用来设定机动车绿灯基础时长 |
| `display_6digit_driver.v` | **6 位数码管动态扫描驱动**（`seg_data[7:0]`、`seg_sel[5:0]`，`hex2seg` 字模）：`adc_en` 有效时左侧三位显示 ADC 值，中间一位作分隔符，右侧两位显示倒计时 |
| `buzzer_pwm_driver.v` | PWM 蜂鸣器输出 |
| `tb_traffic_lights.v` | 空占位文件（0 字节），随该方案一起保留 |
| `Waveform1.vwf` | 该方案的 Quartus 仿真波形 |

**FPGA 设计实现的控制功能**

- 两套设计都有：完全自动定时 **或** 两个行人按钮之一的请求过街。
- OLED 设计：8 位拨码开关给出车流数值，既换算成 `flow_val`，又派生出 5–20 s 的行人等待时间；OLED 显示当前状态、倒计时与车流进度条；行人相位由蜂鸣器提示。
- 数码管方案：车流传感器按键补偿绿灯相位，通过 SPI ADC 读电位器设定绿灯基础时长 —— 调节时显示从倒计时切换为 ADC 原始值，板上能直接看到效果。
- Quartus 引脚分配保存为 `.tcl` 脚本（`quartus-v2/` 用 `pin_planner.tcl`，两个 `quartus-vg*` 用 `pin_assignment.tcl`，`simulation/` 用 `pin_assignments.tcl`），`.qsf` 里是引脚分配与器件设置。
